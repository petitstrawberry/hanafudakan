# バージョンとお知らせの更新

次版は **1.0.0（公開準備中）**。以前のマニフェストは0.1.0で、調査時のmain（5c20bee）にはリリースタグがありません。過去の変更を架空の0.xリリースに分けず、ハイパー花札の初回実装PR #3を含む以降のマージ済み変更と、今回のお知らせ機能を1.0.0に集約しています。公開日が確定するまで `date` は `null` とし、画面には「公開準備中」を表示します。

## 更新手順

1. `client/src/data/releases.json` の先頭に新しい版を追加する。安定版SemVer（例 `1.1.0`）、確定した公開日（`YYYY-MM-DD`、公開前は `null`）、タイトル、概要、初回案内用の短い `highlights`、詳細の `sections` を書く。過去の項目を残し、新しい順・重複なしにする。内容はマージ済みの差分と現在の仕様に照合する。
2. `nix develop --command node scripts/release-version.mjs --write` でclientのpackage/lockとCargoのmanifest/lockを同期する。画面とNixパッケージはJSON先頭の版を直接参照する。
3. `nix develop --command node scripts/release-version.mjs --check`、`nix flake check --no-update-lock-file`、`nix build . --no-update-lock-file` を確認する。Nix checkにも版と記録の整合性検査を含む。
4. ロビーの初回案内、閉じる・Escape・背景クリック後の再起動、一覧・詳細とブラウザーの戻る、招待入室中と対局中の非表示、保存拒否を確認する。任意で `QA_BASE_URL=http://127.0.0.1:3000 PLAYWRIGHT_MODULE=/path/to/playwright QA_CHROMIUM_PATH=/path/to/chromium nix develop --command node scripts/qa-announcements.mjs` を実行する。
5. 承認された公開時だけ日付を確定し、同じ版の `v1.0.0` 形式のタグを使う。既存CIはmainとvタグでGHCRへ公開するため、push自体が公開を伴うことに注意する。今回の作業ではタグ作成・push・PR・公開は実施しない。

## 既読の意味と保存

`hanafudakan-announcements-read-through` に「案内を確認して閉じた最新バージョン」を保存します。初訪問・欠損・不正な値では全記録、既知/記録にない旧版ではそれより新しい全記録を新しい順で案内します。数値比較なので1.10.0は1.9.0より新しく、複数版の飛び越しにも対応。将来版の既読は古い画面から上書きしません。

閉じるボタン・確認ボタン・Escape・背景クリック・「お知らせ一覧へ」は表示した版まで既読にします。一覧・詳細を開くだけでは既読になりません。自動案内は読込完了後、部屋に入っていないロビー、他のモーダルや通信操作がない時だけ。`?room=` 招待URLでは入室を優先し、ロビーへ退室した後に案内します。存在しない招待や入室失敗では解決後のロビーで案内し、合言葉入力中は表示しません。画面上でお知らせを開いても対局のWebSocketと進行は保持します。

既存の `hanafudakan-session`、`hana-name`、音・絵柄のキーは変更しません。サーバー状態も変更しません。localStorageへのアクセス拒否・書込失敗では画面内メモリへフォールバックし、その画面では閉じた案内を抑制します。永続保存できない場合の再読込や端末・ブラウザー変更では再案内されます。ストレージ削除による再案内も仕様です。複数タブではstorageイベントで既読を反映し、古い版を閉じても新しい既読を巻き戻しません。
