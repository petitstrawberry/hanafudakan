# ハイパー調整・検証記録（2026-09-23）

採用ルール：選んだ役だけを賭け金へ移し、双方の取り札を清算して48枚で完全再配布。相手が先手。契約・花力・成長倍率・HPは持ち越す。契約者のあがりには、倍率前の役点合計が契約元の最大役点を超え、最後の契約後にこいこいする必要がある。こいこい前の重ねがけは可能。未契約者は相手の3CHAIN以降、各手番1回の反撃めくりを得る。通常のこいこいには影響しない。

## 比較方法

札の選択は全戦略で同じ `move_value`。差は役成立後の判断のみ。各組み合わせを seed 0〜1999、左右を入れ替えて4,000試合（3局制）ずつ実行した。各再配布案につき3組み合わせ、12,000試合・36,000局。3案を比較したあと、連鎖カウンター上限で同じボーナスが繰り返し発火する点を直し、採用案をさらに12,000試合で再検証した。

- 即あがり：役成立時に必ず得点確定。契約・こいこいをしない。
- 積極契約：契約可能なら最初の候補を必ず契約し、それ以外はあがる。
- 状況判断：CPU本体。捨てる役点と選択役、獲得予告55文未満、HP6超を条件に契約し、それ以外はあがる／こいこいを選ぶ。

## 再配布案の比較

| 清算方式 | 積極契約 対 即あがり | 状況判断 対 即あがり | 状況判断 対 積極契約 |
| --- | ---: | ---: | ---: |
| 相手の全取り札を保持 | 5.88% | 9.10% | 63.05% |
| 双方を清算 | 54.30% | 57.83% | 51.73% |
| 相手の最上位の成立役だけ保持 | 54.30% | 57.83% | 52.52% |

表は左側戦略の試合勝率（引き分けも分母に含む）。全取り札を相手に残す案は契約側に不利すぎた。成立役だけ保持する案と全清算は近く、条件分岐が少なく配札が必ず8/8/8/24になる全清算を採用。即あがり相手では相手の成立役がまだないことが多く、後者2案の結果が一致している。

## 再配布調整時点のリスク（今回の反撃調整前）

| 戦略対戦 | 左勝 / 右勝 / 引分 | 契約した側が敗北・流局した割合 | HP戦になった局 / K.O.局 |
| --- | ---: | ---: | ---: |
| 積極契約 対 即あがり | 2172 / 1815 / 13 | 49.36% | 1764 / 1188 |
| 状況判断 対 即あがり | 2313 / 1677 / 10 | 46.08% | 1240 / 800 |
| 状況判断 対 積極契約 | 2070 / 1921 / 9 | 32.39% | 4926 / 4217 |

契約は成功時の点が大きい一方、積極契約でも即あがり相手に約45%の試合で勝てていない。契約した人の局単位で見ると約半数が賭け金を失う。平均得点だけでバランスを判断せず、3局を通じた勝敗を主指標にした。

## 連鎖への反撃とあがり条件（2026-09-23追試）

この時点では、連鎖の追加めくりと倍率を維持し、契約者だけが契約元の役点以上の単独の役を作らないと「あがる」を選べないようにした。複数契約では最大値で、合計値にはしない。K.O.はこの条件の対象外。未契約側は相手が3CHAIN以上になった後、通常めくりの後に各手番1回だけ反撃めくりを得る。これによりハイパー返しを待たずに札と役を取り返せる。以下の「採用版」はこの当時の「以上」判定による結果である。

同じseed 0〜1999を左右入れ替えた4,000試合（3局制）ずつ再実行した。CPUの札選択は全案で同じ。

| 戦略対戦 | 従来版 左勝 / 右勝 / 引分 | 採用版 左勝 / 右勝 / 引分 |
| --- | ---: | ---: |
| 積極契約 対 即あがり | 2172 / 1815 / 13 | 1762 / 2217 / 21 |
| 状況判断 対 即あがり | 2313 / 1677 / 10 | 1998 / 1988 / 14 |
| 状況判断 対 積極契約 | 2070 / 1921 / 9 | 2095 / 1901 / 4 |

状況判断対即あがりは57.83%から49.95%へ。反撃開始を早めて毎手番1回にする案は43.4%、3CHAIN以降に2回与える案は42.15%、早期1回＋3CHAIN以降2回は36.05%（各2,000試合）で、契約側が不利になりすぎた。採用版は連鎖を消さずに、相手の役作りを助ける。

単局CPU同士2,000局では、最初に契約した側の勝利が1585/1940から1505/1940へ、相手が役の判断画面に到達した局が834/1940から1074/1940へ変化した。先に契約した局だけの条件付き指標なので、実力差を表す値ではない。

## 連鎖・終局（CPU同士2,000局）

| 指標 | 変更前 | 「以上」判定版 |
| --- | ---: | ---: |
| 流局 | 1061/2000 | 35/2000 |
| 状態に3CHAIN以上が現れた局 | 4/2000 | 1930/2000 |
| 再配布直後に山札が空になった回数 | 1838 | 0 |
| 一人が2契約以上を得た局 | 273 | 1239 |
| 1局の操作数 中央値 / 95%点 / 最大 | 26 / 29 / 32 | 26 / 41 / 60 |
| 獲得点 中央値 / 95%点 / 最大 | 0 / 11 / 41 | 75 / 184 / 322 |

操作数はplay/choose/decision等のサーバー操作であり秒数ではない。変更前は毎手番CHAINをゼロにしていたため、CHAIN指標の定義自体が異なる。変更前後には効果・配札・CPU判断の変更も含まれ、単独変更の因果効果を表す比較ではない。

## あがり条件を「超える」に変更（2026-09-23）

契約コストと同点の役では上がれないように変更。5文の役が2つあっても、倍率後の得点が高くても、5文契約には6文以上の単独の役が必要。K.O.は対象外。上の「以上」判定と同じseed 0〜1999・左右入れ替え・各4,000試合で再実行した。

| 戦略対戦 | 「以上」左勝 / 右勝 / 引分 | 「超える」左勝 / 右勝 / 引分 |
| --- | ---: | ---: |
| 積極契約 対 即あがり | 1762 / 2217 / 21 | 1395 / 2590 / 15 |
| 状況判断 対 即あがり | 1998 / 1988 / 14 | 1523 / 2462 / 15 |
| 状況判断 対 積極契約 | 2095 / 1901 / 4 | 2001 / 1991 / 8 |

全試合が終局し、最大操作数は212（上限500）。状況判断対即あがりの勝率は49.95%から38.08%に下がった。契約を使う戦略には明確に厳しい境界変更であり、倍率だけではあがり条件を満たせなくなる。

## 役点を合算し、契約後のこいこいを必須に変更（2026-09-23）

倍率前の役点合計が最大契約コストを超え、最後の契約後にこいこいしていればあがれる。契約前のこいこいは数えない。こいこい前でも次の契約は可能で、重ねがけ時には必要なこいこいを更新する。K.O.は両条件の対象外。

同じseed 0〜1999・左右入れ替えで各4,000試合を再実行した。あがりの点数条件だけを合算へ変え、こいこいを不要にした比較案も実行した。

| 戦略対戦 | 単独役＞コスト | 合算＞コスト＋契約後こいこい | 合算＞コスト、こいこい不要 |
| --- | ---: | ---: | ---: |
| 積極契約 対 即あがり | 1395 / 2590 / 15 | 1493 / 2493 / 14 | 1587 / 2398 / 15 |
| 状況判断 対 即あがり | 1523 / 2462 / 15 | 1718 / 2267 / 15 | 1939 / 2047 / 14 |
| 状況判断 対 積極契約 | 2001 / 1991 / 8 | 2059 / 1936 / 5 | 2060 / 1936 / 4 |

合算＋こいこい案の状況判断対即あがり勝率は42.95%。単独役条件の38.08%より緩和され、こいこい不要案の48.48%より契約にリスクが残る。全試合が終局し、最大操作数170（上限500）。

## 再実行

```sh
nix develop --command cargo test hyper_balance_simulation -- --ignored --nocapture
HYPER_RESET_VARIANT=0 nix develop --command cargo test hyper_strategy_simulation -- --ignored --nocapture
HYPER_RESET_VARIANT=1 nix develop --command cargo test hyper_strategy_simulation -- --ignored --nocapture
HYPER_RESET_VARIANT=2 nix develop --command cargo test hyper_strategy_simulation -- --ignored --nocapture
HYPER_BALANCE_VARIANT=0 nix develop --command cargo test hyper_strategy_simulation -- --ignored --nocapture
HYPER_BALANCE_VARIANT=3 nix develop --command cargo test hyper_strategy_simulation -- --ignored --nocapture
HYPER_BALANCE_VARIANT=8 nix develop --command cargo test hyper_strategy_simulation -- --ignored --nocapture
```

VARIANT 0は相手保持、1が本番の全清算、2は相手の最上位役保持。比較用分岐はテストビルドだけに存在する。旧版の結果は変更前ソースで取得した記録であり、現在のVARIANT 0は「新効果＋相手保持」の比較である。生ログとJSONは `artifacts/hyper-balance/` に保存。

`HYPER_BALANCE_VARIANT=0` は反撃・あがり条件なし、`3` は採用版、`8` は役点合算だがこいこい不要の比較案。候補1〜7もテストビルドで比較できる。`HYPER_SIM_SEEDS` でseed数を変更できる。

## 検証と限界

- Rustの回帰テスト：最終手番での契約、双方没収、48枚の一意性、再配布時の山札24枚、二重送信、盤面revision、HPの即時K.O.、非契約者の反撃、倍率上限、追加めくり上限、次局の初期化。
- API層でも実際のHyperコマンド→ブロードキャストを検査。観戦者へ手札・山札を漏らさない。
- 対戦シミュレーション中は全操作で48枚の保存、再配布後の山札、終了までの上限を検査。
- UI補助試験：開発サーバーの `/qa/hyper.html`。実GameRoomへ合成スナップショットを渡し、契約・再配布・HP・CHAIN・K.O.を確認できる。本番ビルドのエントリには含めない。
- ハイパー状態は両者の名前欄へ統合。対局はスクロールせず画面内に収める固定領域配置。390×844・1440×1000・844×390でHP有無／こいこい／倍率変更時の領域位置・高さの変化0px、ページの縦横はみ出し0pxを確認。
- 場は8枚まで4×2、9〜10枚は5×2、11〜12枚は6×2。以降も最大2段で縮小する。HP攻撃は場札から相手HPへの飛翔→着弾とHP減少→ダメージ数値・衝撃音・320msの揺れを順に再生する。動きを減らす設定では飛翔・揺れを省く。
- CPUの近似方策同士の結果であり、最適戦略・全契約の同等な強さ・人間の面白さを保証するものではない。人間同士の実戦から追加調整する余地はある。

## 演出実装後の最終確認

最終版で12,000試合・CPU同士2,000局を再実行し、上記の結果が再現した。Rustはシミュレーションを含む51テスト、Clippy、クライアント36テスト、TypeScriptと本番ビルドが通過。ログは `artifacts/hyper-balance/final-simulation-validation.txt` と `final-ui-validation.txt`。

UIでは通常待機→開始、24枚の配札（相手8枚は裏向き）、契約カットイン→再配札、通常／ハイパーBGM切替と個別スイッチ、双方へのHP攻撃、K.O.爆発中は勝利画面が出ず爆発終了後に出る順序を確認。375×667を含む縦横4サイズで固定領域とスクロール無しを確認した。合成局面の操作メニューは盤面を押し下げないオーバーレイにした。
